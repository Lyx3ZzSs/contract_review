# 配置规则修订

`review-configured-rules-v1` 并行执行基础规则和累计责任核查。程序从本轮意见中选取有原文依据的局部拟稿目标。每条候选改文关联本轮意见，并校验原文、目标位置、数值和实际写入范围。涉及同一写入位置的候选稿会在汇总时检查冲突。

批量候选稿校验后，只对缺少有效改文的意见单独重试。仍未取得有效改文时，风险意见继续显示，拟稿阶段记录具体失败原因。改文交付后由审阅人确认和应用。审查生成过程不直接修改正文。

## 执行与恢复

执行快照记录合同解析、规则核查和按需启动的局部拟稿。人工处理独立记录。模型响应按调用保存到 `review_checkpoints`，恢复时重新执行本地校验并复用成功调用。请求传输重试和结构校验重试分别记录，旧执行者无法覆盖新批次。

`POST /api/v1/runs/{id}/resume` 恢复失败或部分完成的任务。已有人工处理、执行版本变化或旧策略退役时，重试创建关联的新批次。历史结果、批注和修订记录可继续查看。

## 异常与写入

商务待确认与文档写入权限分开：`context_required` 的有效候选稿可由用户选择接受修注、添加批注或接受修订，包含占位的文本仍作为审阅稿保留，采纳不改变风险或商务确认状态。批注同时携带待核对说明。物理写入范围重叠时仅开放添加批注；无效证据、过期原文、只读会话仍阻止写入。`proposal-availability` 按操作返回可用模式和阻断原因，与写入接口共用校验；审查完成后前端重新加载权限。保存仍须验证 DOCX 正文、书签、修订与批注后才标记成功。

OnlyOffice 仍使用现有保存核验、修订、批注与撤销流程。生成过程不写正文。历史任务保留原结果，新流程通过新一轮审查作用于当前保存版本。


### 批注与修订连续操作

文档操作按批注和正文修订分别计算完成状态。先添加批注后可补做修订，先修订后可补加批注；组合操作只执行缺项。风险及商务确认状态保持独立。每次请求保留 `requested_mode`，`mode` 表示实际执行方式；批注后补做修订使用组合方式迁移原批注，避免原生替换删除其锚点。仅迁移未解决、无回复、内容未改变的自有唯一批注，存在重叠批注或回复时说明原因。

保存核验使用目标段落及书签的字符范围、对应插入/删除文字、完整批注内容和范围，并校验原有批注内容与作者。不能用全文修订数量增加或其他位置存在相同批注证明成功。删除记录位于插入记录前后均可，但必须紧邻目标范围且原文完全一致。

`prepared` 操作按 `phase` 区分准备和已保存待核验，核验失败持久化具体原因。消息超时只查询编辑器操作记录，不重复执行内容命令；原会话关闭后，新可写会话可根据已保存文件及原保存回执恢复确认。取消操作要求同合同可写会话、未改变的保存版本和明确的写入前拒绝或只读缺失回执；不确定结果走保存核验或撤销恢复。撤销最近一步恢复此前精确文件字节，保留前一步状态，并允许继续撤销恢复后的最近一步。

写入范围仍为普通单段替换与批注。插入/删除、多段与表格写回、用户编辑候选稿和批量采纳尚未启用。

### 正文变化后的重新定位与适用性复核

保存正文后，修改建议按原始完整段落重新定位。唯一段落支持前文增删和段落移动；重复段落只有在所有最优顺序对齐均指向同一位置时才允许复用。目标段落已改变、已删除或位置不唯一时保留具体原因，不按近似文字自动写入。

正文发生语义变化时，前端自动请求 `POST /runs/{rid}/proposal-rechecks`。模型对照原审查和当前完整正文，逐项核对旧候选稿是否仍然适用，包含跨条款定义、金额、责任与优先适用规则的影响。每份候选稿必须得到独立结果；受影响的建议仅开放批注，通过的建议可继续接受修订。复核不重写候选稿，不替代整轮审查，不确认商务条件或风险处理结果。

结果绑定保存版本及审查立场、阶段、资料和原候选稿。再次手工修改正文会使旧结果失效；同轮已核验的建议操作和撤销沿用对应结果。立场、阶段或资料改变要求重新审查。并发请求复用进行中任务，超时与模型失败明确显示并支持手动重试；迟到回执不能覆盖新尝试。每次请求最多处理40份候选稿，完整输入上限80000字符，超限明确失败，不截断正文放行。

2026-11-17 使用两份合成合同和真实配置模型验证：新增归档说明后两份建议均可复用；新增“任何责任上限均不适用”的关联条款后，仅责任建议被阻断，付款建议仍可采纳。OnlyOffice 中实际完成重新定位后的修订加批注，以及受影响建议的单独批注，均通过保存核验。基线审查结果为测试夹具，适用性结果来自真实模型；证据保存在 `.local/proposal-recheck/`。

## 原生条款树（clause-tree-v2）

新上传和编辑器保存产生的文档版本同时保存条款结构快照。`docx_structure.py` 读取 OOXML 标题、大纲级别、样式继承和自动编号定义，处理多级计数、重启、覆盖与常见中文/数字/字母/罗马编号。编号单独保存在 block 元数据中，不拼入 `blocks.text`；原有段落 ID、修订视图和字符位置不变。

`clauses` 是以文档为隐式根的节点表，`parent_id=null` 表示文档直属节点。节点含类型、编号、标题、顺序、直接拥有的 `source_spans`、判断来源、状态及缺口。父节点的子树范围按父子关系计算，不重复存储子节点正文；`block_ids` 是直接来源索引，保留兼容。表格作为完整节点挂到所属条款，附件单独开启结构范围。节点 ID 只保证同一文档版本与结构解析版本内可复现。

建树后校验父节点存在、无环、来源范围合法以及每个正文字符恰好直接归属一次。无法还原的编号、缺失上级和单段多个条款标记保留原文并标注待核对，不生成假定编号或自动切断原文。跨条款定义、例外等语义关系不属于这棵结构树；PDF/OCR 和模型辅助结构恢复尚未接入。

版本读取端返回已存快照；旧版本缺少结构时使用固定的 v1 规则回退，不用 v2 静默重组历史结果。工作台使用条款树归组结果和生成证据引用，表格风险归入所属条款。

相关回归：`test_native_clause_tree.py`、`test_review_reading_plan.py`、`test_proposal_operations.py` 及 `frontend/tests/clause-tree.test.mjs`。合成文档浏览器验证证据保存在 `.local/clause-tree-verification/`。
