# ONLYOFFICE 接入

本项目将 DOCX 版本保存于业务数据库，ONLYOFFICE 通过签名 URL 加载文档并回调保存结果。编辑器成功执行操作不等于业务版本已保存；审查和导出均等待保存确认。

## 独立部署依赖

当前 `backend/app/onlyoffice.py` 固定适配构建 `10.0.0-labesign9`，对应 Document Server 10.0.0-169 的定制前端与消息桥接。该编辑器部署位于独立工程，不包含在本仓库中。

宿主通过 `frontend/src/editors/onlyoffice-client.ts` 交换带请求 ID 和文档 key 的消息，核对消息来源与编辑器窗口。正文定位需要编辑器实现相应桥接协议。普通官方镜像不保证具备此桥接，也不能据此声称定位、保存保护等功能已完成接入。

本项目使用普通插件及定制桥接，不依赖 Automation API。普通单段建议写回和原生批注通过 navigation 24 白名单桥接开放；外部批注／修订列表仍关闭。保存、撤销及限制见 integrations/onlyoffice/README.md 的“建议应用与原生批注”。

## 环境变量

API 启动前设置：

```sh
export RIXIN_ONLYOFFICE_ENABLED=1
export RIXIN_ONLYOFFICE_PUBLIC_URL=http://127.0.0.1:18083
export RIXIN_ONLYOFFICE_INTERNAL_URL=http://127.0.0.1:18083
export RIXIN_ONLYOFFICE_APP_URL=http://host.docker.internal:8010
export RIXIN_ONLYOFFICE_SECRET_FILE=/absolute/path/to/private-secret-file
```

密钥文件使用纯密钥或单行 `JWT_SECRET=<value>`，需与 Document Server 一致；也可通过 `RIXIN_ONLYOFFICE_SECRET` 注入。密钥只保存在服务端，不写入前端或 Git。

`PUBLIC_URL` 是浏览器访问地址，`INTERNAL_URL` 是 API 请求编辑器命令和文件的地址，`APP_URL` 必须可由 Document Server 容器访问。容器回调宿主 API 时，API 需监听容器可访问的地址；例如本地开发可使用 `--host 0.0.0.0`。更换 API 端口时同步修改 `APP_URL`。

## 编辑和审查行为

当前限制单写会话；历史定稿与新的审阅完成记录均不再锁定正文，其他窗口因写会话占用而只读。编辑默认启用跟踪更改，修改保留为修订记录。业务版号确认后才显示保存完成。

新审查先持久化按正文位置排序的阅读目录。默认跟随实际开始的核查任务及已校验意见，不再按固定时长逐段播放。当前单元仍有任务执行时保持位置；任务完成后继续跟随其他已开始的核查点。意见待处理、任务失败或意见回执晚到不会阻塞其他核查；后台结束后停止自动跳转，进入结果浏览。迟到及修订意见更新卡片，不自动回跳已浏览位置；可主动继续浏览或选择事项。没有独立核查任务的阅读单元不自动播放，仍可从目录访问；手动选择目录、上一条或下一条会切换为手动阅读。450ms 只用于合并相邻导航操作，不是条款审查时间。过程展示使用独立证据标记层，不修改 DOCX 高亮格式，也不保留新的原生选区。审查期间正文自动只读，只读切换成功后开始跟随；仅鼠标移动和焦点变化不触发暂停；正文滚轮、指针按下和键盘操作暂停跟随。审查结束或失败后恢复修订编辑，被其他写会话占用的文档仍保持只读。界面提供恢复和关闭控制。

主动点击原文引用时，如正文尚未保存，先等待保存确认，再将历史审查引用映射到当前版本。整段未变时按唯一全文或所有最优顺序对齐均一致的位置绑定；段落变化时，用已确认的前后段落限定变化范围，再按字符对齐重新计算 Unicode 码点偏移。引用仍在时定位当前引用；引用变化或范围不再唯一时，只有对应段落有足够且无歧义的保留文字才定位当前整段，并提示旧意见尚未重新验证。引用跨拆分段落时只选中起始片段并明确提示。已删除、无法区分的位置以及超过对齐预算的变化范围保留具体失败原因。编辑器仍验证当前版本、保存状态、编辑代次和实际选中文字。导航迁移仅供查看，不放宽修改建议的写入或适用性校验。

开发验证入口为 `/onlyoffice-integration.html?id=<test-contract-id>`，仅接受 `data_purpose=test` 的合同；测试文件使用 `backend/tests/fixtures/` 中的合成样本。

测试桥接和保存回调可使用 `backend/tests/probes/onlyoffice_collaboration.py`。探针应使用独立数据库，不使用业务合同。停止服务前完成保存；停用编辑器仅关闭能力开关，不删除数据库或回滚文档。


## 顺序审阅导航（2026-11-13）

阅读目录包含编号条款、未编号段落、表格段落和未还原的 Word 自动编号；目录数量是阅读单元数，不是法律条款数量。每个可解析文本块只映射一次。候选责任筛查、全文抽取任务、最终规则核验分别展示；失败、待材料和未发现候选不能当成“全文无风险”。后台仍使用有限并行核查。

支持上一条、下一条、目录定位、滚动暂停和恢复。审查后台结束后继续浏览剩余单元。当前标签页按 run/version/attempt/plan revision 保存阅读位置和暂停状态，只保存定位标识，不保存合同原文；重试或版本变化不复用旧位置。

居中适配器及部署工具随工程保存在 [integrations/onlyoffice](../integrations/onlyoffice/README.md)。适配固定 `10.0.0-labesign9` 构建，能力版本 `navigationVersion: 13`。短选区以正文视口中心为目标，长选区以起点为目标；支持滚动边界确认、稳定回执及 reduced-motion。正文滚轮采用捕获阶段监听，避免被编辑器截断；程序滚动不会误判为用户操作。

`VITE_LIVE_REVIEW=0` 可关闭过程展示和自动跟随。结构能力缺失时拒绝结构定位；仅居中能力缺失时保留已校验的原文选区并提示。重复正文、普通表格中的相同签章、跨页长段已有实际样例验证；未还原自动编号、图片、复杂嵌套结构不能假报已完整覆盖。定位失败保留待定位位置，恢复后重试。

### 关联核对与当前条款意见

当前条款意见卡展示问题、原文与关联依据、建议或下一步核对，以及人工处理状态。新意见追加到已有卡片之后，更新不重排已有卡片或强制展开其他意见。已处理意见保留在当前条款中；全局待处理数量仍按服务端人工决策计算。

查看正文关联证据时，暂停跟随并保存原阅读锚点；连续查看多处证据仍返回首次出发的条款。“返回原条款”只恢复正文位置，保持暂停，用户再决定恢复跟随或进入下一条。返回前不能直接恢复自动跟随。失败或用户滚动不会丢掉返回位置，新阅读目录选择则结束此前核对。

返回记录按审查批次、正文版本、执行尝试和计划版本隔离，只在当前标签页保存不含原文的锚点键。刷新后重新从本轮有效计划与证据中解析；旧批次的记录不用于新批次。定位继续复用保存版本校验与编辑器结构定位，未绕过保存、只读、过期检查。附件证据沿用卡内材料预览，不将其冒充当前正文位置。

当前意见卡复用现有人工决策接口，核查进行中、上下文变化或保存未确认时禁用处理；用户打开卡片或处理弹窗时暂停跟随。记录处理不会修改合同，也不会把阅读进度计作处理完成。

本次交付覆盖结构计划、顺序阅读、只读与居中这一首期流程。独立的逐规则全量条款台账、完整跨条款二次复核调度、局部重审与谈判记忆仍未启用；既有全量重审和人工确认继续生效。事件沿用已有 seq/attempt 协议，新增兼容的 plan_ready，没有将全部协议切换为规划中的 schema v2。

## EigenPal 只读对照原型（2026-11-13）

`frontend/editor-comparison.html` 是开发验证入口，不进入生产构建。只接受 `data_purpose=test` 的合同，以同一版本的 DOCX 和证据运行两种编辑器。入口复用 `reduceExecution`、`followTargets` 和 `createReviewFollower`；控制按钮生成明确标识的受控事件，不启动模型、审查作业或写入审查结果。

从仓库根目录执行 `python3 frontend/scripts/create-editor-comparison.py` 可生成合成合同并打印入口地址，所用 Python 需要 `python-docx` 和 `httpx`。脚本保留测试合同供人工查看，不读取业务材料。API 默认端口为 8011，可通过 `--api` 指定隔离测试实例。启动原型：`npm --prefix frontend run dev -- --config vite.comparison.config.ts`。EigenPal 使用 5176；OnlyOffice 使用现有桥接允许的 5175，其前端应代理同一个测试 API。不要通过扩大桥接来源白名单解决验证入口问题。

核心包固定为 `@docx-editor.dev/core@2.37.0`，仅使用 Apache 2.0 核心功能；字体来自对应版本的 `fonts` 和 `fonts-cjk` 包。未引入 Pro、Editor API、收费批注或修订模块。字体资源从本地包提供；Vite 排除字体预打包以保留资源 URL，并启用支持顶层 await 的依赖转换目标。正式入口不导入 EigenPal。

适配器先逐段核实完整文字、空段序号与快照版本，再取得原生节点身份；长段落使用有长度上限的前缀查询取得节点，不以该前缀替代全文校验。证据从 Unicode 码点偏移转为 UTF-16，支持重复段落和同段重复句的精确范围。结构、版本或引用不一致时拒绝定位。高亮为独立视图层，不移动选区；短证据居中，长证据起点放在视口上方四分之一处。首尾阅读留白使边界条款也能居中。近距离移动可中断，远距离直接定位；支持 reduced-motion。

本轮合成样本两种引擎均成功定位 23/23 个位置。EigenPal 的 22 个短证据居中误差小于 0.5 CSS px；另一个超长证据按起点展示。受控事件验证通过等待期间不轮播、意见卡持续更新、关联核对返回、滚轮暂停恢复、取消定位及只读。108 项前端测试通过，生产构建通过。

不能据此整体替换：同一 DOCX 在 EigenPal 中为 2 页，在 OnlyOffice 中为 3 页，存在字体替代、行距和分页差异。自动化环境这一轮定位回执 P95 分别约 417 ms / 391 ms，未证明 EigenPal 更快。样本量和后台帧调度不支持推断真实用户的帧率或大文档内存。完整版式保真、长文档资源占用、保存往返、批注修订和真实 Agent 决策质量均不属于本轮已验证能力。


## 借鉴 EigenPal 的事项连续展示（2026-11-13）

本阶段接入现有 OnlyOffice 审查页。借鉴的是身份稳定、证据标记与原生选区分离、按需滚动的设计；正式入口继续使用 OnlyOffice。

新增 `review-matters.ts` 将已锚定任务与意见关联为核查事项，优先使用明确的 `event_id / rule_id`，兼容已有复合任务 ID。同一正文段落的不同规则不合并。主面板围绕当前事项展示状态、意见和关联依据，正文目录折叠为辅助入口。意见更新、增加证据和其他任务启动不更换当前事项；选择下一事项是明确操作。

跨条款核对保留当前事项卡和人工处理状态。返回事项原文后保持暂停；刷新恢复核对记录时显示“关联核对已暂停”，不假称已恢复正文位置。任务失败显示“核查未完成”，不推断没有风险。

桥接新增 `presentEvidence / clearEvidence`，宿主要求 `navigationVersion >= 13` 和 `evidencePresentation` 能力。可见证据原地标记，离屏证据按需滚动，意见更新不驱动滚动。使用纵向条绝对滚动绕开 SDK 的滚轮距离修正，同步恢复测量前的选区和位置，布局后复核实际可见性。单行证据框选；跨行、跨页仅标记起点，完整引用由事项卡展示。具体边界与部署方式见适配器 README。

验证使用合成合同、实际 API 持久化执行事件、现有审查页及固定版 OnlyOffice，不调用真实审查模型。覆盖重复段落、同段重复句、Unicode、跨页长段和表格，以及事项更新不抢占、关联往返、刷新恢复、失败状态。该验证证明联动实现，不代表模型审查质量或自主规划能力提升；后台并行调度、完整复核策略和审查决策机制未在本阶段改变。


### 自动跟随停留修复（2026-11-13）

取消“发现意见后必须人工继续”的自动跟随门槛。意见人工处理与后台任务执行分离：当前任务未结束时保持原位；结束后允许跟随其他实际开始的任务，不需要先记录处理意见。任务已返回但意见晚到时，也不阻塞其他任务。仍保留主动滚动、打开卡片及关联核对时的暂停，手动模式不会自行前进。

`needs_input / completed / failed` 等终态停止自动导航，显示“本轮自动核查已结束”，将控制区改为“核查结果浏览”，提供“继续浏览意见”。即使保存了暂停或手动阅读状态，结束提示也不会被旧停留消息覆盖。待处理意见不等于后台仍在执行，更不等于审查通过。终态不会自动播放积压意见；显式浏览仍可定位。

## 正文渐进加载（2026-11-16）

宿主不再使用覆盖正文的 `.editor-loading`。文件名栏显示连接、打开正文、准备审阅功能等真实阶段；`onDocumentReady` 记录 `document.visible`，桥接版本与能力校验、初始修订模式确认后才开放输入及业务操作。初始化中的 iframe 容器使用 `inert`，正文画面仍可见；需要用户完成原生打开操作时暂停计时并开放文档窗口，正文就绪后恢复初始化门禁。

8 秒后显示等待较长提示，打开阶段 45 秒、正文就绪后的集成阶段 25 秒超时进入错误状态。迟到响应不得恢复已失败的初始化。错误提示占据正文下方的正常布局，不覆盖内容；原生加载错误与桥接错误分别说明正文不可用或审阅能力不可用。无未保存修改时可从失败状态直接退出会话。拼写提示与审阅页签选择在能力就绪后执行，每条等待上限 1.5 秒，失败只提示，不回退正文就绪状态。

## 页面地址与刷新恢复（2026-11-16）

工作台、规则中心、审阅室分别使用 `#/`、`#/rules`、`#/contracts/<contract-id>/review`。Hash 路由兼容现有静态部署，无需新增服务端路径回退；地址不携带合同正文或会话令牌。直接访问或刷新审阅室时，只读取指定合同及其审阅状态，不依赖工作台列表或 `last-document`。无效路径、合同不存在、加载失败和未上传正文分别保留明确状态与返回入口。

页面内导航和浏览器前进后退共用保存及关闭会话屏障；失败时恢复当前地址并保留编辑器，连续后退在保存结束后采用最后目标。同一路由的 iframe 历史变化不关闭文档。“重新加载”仅重建编辑器并复用当前会话恢复信息；存在未确认修改时先等待保存成功，不重载整个页面。撤销已保存操作、过期会话恢复、重新开启审阅所触发的整页刷新也会由地址恢复当前合同。
