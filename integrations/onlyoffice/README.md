# OnlyOffice 审查事项与证据展示适配器

`navigation-bridge.js` 是本项目可交付的完整桥接文件，对应独立 `onlyoffice-ui-lab` 工程的 `visual-source/integration-bridge.js`。它保留已有保存屏障、原文验证、只读模式与严格 origin / documentKey 校验，不开放通用 SDK 调用。

适用范围：`10.0.0-labesign9` 固定构建，`navigationVersion: 33`，`evidencePresentation: true`。使用该构建的 `AscBuilder.sb.GetDocument()` 段落包装器和 `Asc.editor.wa.MA` 纵向滚动条；内部路径不承诺跨版本兼容。缺少结构、选区恢复或绝对滚动能力时明确拒绝展示，不能假报定位成功。

安装前保存独立工程当前版本。以下命令先校验两份现有资源清单，默认仅报告差异；增加 `--apply` 才写入源文件、构建产物、部署副本及资源哈希：

```sh
python3 integrations/onlyoffice/install-navigation.py --lab-root /absolute/path/onlyoffice-ui-lab
python3 integrations/onlyoffice/install-navigation.py --lab-root /absolute/path/onlyoffice-ui-lab --apply
python3 /absolute/path/onlyoffice-ui-lab/deploy/prepare.py
```

本地运行服务将发布目录只读挂载到容器；更新宿主发布文件即可生效，刷新编辑页面加载 `?navigation=33&v=<桥接内容哈希>`。不需要替换合同文档或许可文件。生产部署应重新构建固定发布包，不能把本地实验目录当成可变生产发布目录。

回退：关闭宿主 `VITE_LIVE_REVIEW`，并按独立工程备份恢复桥接、index、build.py 与两份 manifest。重新部署或恢复后刷新编辑页面。请勿用删除审查记录回退。

验证命令：`node --test integrations/onlyoffice/navigation-bridge.test.mjs`。另外需要在真实固定构建上验证中文原文、居中误差、滚轮暂停和未保存内容保护；模拟测试不能替代实际编辑器验收。

## 结构定位与阅读节奏

宿主先发送 `bindAnchors(version, blocks)`，再发送 `locate(version, blockId, start, end, paragraph, quote)`。绑定比较完整有序段落序列的最早和最晚嵌入；只有二者相同的段落才接受。允许编辑器额外生成页码字段，但不会凭全局第 N 次命中猜位置。允许段末空格差异，保留原始文本校验；文档版本、正文修改状态、段落内容和证据字符偏移都必须通过校验。

2026-11-19 修复表格单元格结束制表符与自动编号段落造成的连锁定位失败：完整映射和降级映射统一使用去除段尾 ASCII 空白的比较键；个别无候选段落只影响自身，其余段落仍须在完整有序嵌入的最早和最晚位置一致时才能绑定。若剩余序列无法完整嵌入，仅保留两侧唯一、无多对一冲突的文本身份；重复内容不按第 N 次命中猜测。

显式导航允许一种受限位置转换：源段开头的制表符被编辑器吸收到自动编号格式时，必须通过原生段落 JSON 确认 numPr，且除这些制表符和段尾空白外完整正文一致。先校验源引用及 Unicode 字符偏移，再转换为编辑器正文范围，并核对实际选中文字。不会删除段内空白、改数字或忽略实际正文差异；纯格式范围不定位。修订写入仍执行严格重新绑定，不使用该导航转换。

使用四方电力交易数据服务合同的同一 DOCX 在只读诊断编辑器验证：映射由107/168恢复到168/168；负荷预测标题、表格描述、正文服务范围、验收款、质保款和段尾制表符段落均定位成功，编辑器未产生修改。复现与验收记录位于主工程 `.local/navigation-root-cause-20261119/`。部署按内容哈希更新脚本 URL，已有页面需重新加载编辑器；不修改业务文档或审查结果。

定位在已绑定段落内使用 `Search` 获取真实范围，并核对候选的文字和 SDK 起止位置。候选范围不合格时，按已绑定段落的内容前缀重新计算 SDK 位置。选中后再核对实际选区的文字和起止位置。若范围 JSON 将全角空格转成半角空格，只有两种表示的非空格字符及空格位置逐一匹配时，才从编辑器的范围原文取回实际字符。选区丢失时，在正文未变且用户未打断的前提下重建一次。选区不写入格式、不插入书签、不改合同。

navigation 25 修复自动编号条款的选区核验：`asc_GetSelectedText()` 可能包含生成的编号及制表符，此时使用实际选区 `GetRangeBySelect().GetText({Numbering:false})` 与原文精确比较。不会通过删除任意前缀或模糊匹配放宽校验，正文不一致仍返回失败。

## 点击引用的原生高亮

审查面板在 OnlyOffice 中点击意见、原文引用或修改位置时，优先调用 `locateReviewTarget` → `locate` → `range.Select()`，由编辑器绘制原生文字选区。定位前清除旧覆盖层，不再叠加紫色逐行下边线、段落范围底色和页边状态浮签。一次只选中当前引用；右侧引用状态在定位成功后更新。用户自行选择或点击正文时，由编辑器接管选区；后台审查更新不重建选区。

该路径沿用完整段落映射、版本与字符范围校验。选区本身不修改 DOCX 格式，不触发保存或创建版本；后续用户对选中文字的编辑仍按正常修订、保存流程处理。高亮颜色由当前 OnlyOffice 原生主题决定，不强制改写编辑器选区样式。

固定构建的 Builder `Select()` 只更新逻辑范围；桥接随后调用 `wq()`（原生 `Document_UpdateSelectionState`）刷新选区画布，再进行居中。仅校验选中文字不够，必须实测蓝色选区确实可见。navigation 20 才具备此刷新步骤，旧资源需要刷新加载。

## 独立证据标记（保留能力）

宿主使用 `presentEvidence({targets, reveal})` 展示当前证据及最多 7 处关联证据，`clearEvidence` 清除。`reveal=never` 只更新标记；`if-needed` 在证据可读时不滚动；`center` 仅供显式定位。三者均复用版本、正文、结构映射与引用偏移校验。证据标记是 iframe 内不可交互的视图层，不改合同格式、批注或修订。

固定构建使用原生选区绘制路径获取逐行几何：逻辑文档 `KK` 对应 `DrawSelectionOnPage`，绘制文档 `lWb` 对应 `AddPageSelection`。同步临时选择前用 `Az` 保存原生选区状态，结束后通过 `xB` 恢复，包括正反向选择。绘制回调仅收集文档毫米坐标，不改原文、不长期占用选区；回调和矩阵在 `finally` 中恢复。再使用 `G9e / uba / $p()` 消费延迟光标回显，并恢复绝对滚动位置。

原生绘制可能重复上报区域，先去重再保存。跨行文字按行高亮，跨页文字分别绘制；当前锚点所在段落另有浅底和边线表达核查范围。这里的范围是已验证的当前段落，不宣称已覆盖整个多段条款。旋转文字或无法可靠取得逐行几何时，明确降级为“仅标出起点，范围未展开”，不画猜测矩形。

宿主可传 `context: {title, phase}`；phase 为 queued/checking/settling/attention/incomplete/finished/context。正文页边标签只展示实际任务状态。`evidenceContext({version, blockId, context})` 仅更新当前锚点标签，供暂停跟随时同步真实任务结果，不测量、不滚动、不改变用户选区。

覆盖层复用节点；文档坐标按照当前页面位置和缩放投影，仅绘制可见片段。每帧检查视口变化，但相同坐标不重写 DOM。修改正文或页面尺寸不再匹配时清除旧几何；缩放和滚动更新投影。未知构建不得直接沿用内部成员名。

近距离移动最多约 240ms；跨越 1.5 个视口、减少动态效果或帧等待超过 60ms 时直接定位。正文滚轮、指针按下和键盘操作暂停跟随，但保留可见证据与范围，并在页边显示暂停状态。程序滚动不触发用户操作通知。保留旧 `locate` 接口供显式原生选区操作，不作为自动跟随呈现路径。

## 事项与真实任务驱动

前端按任务身份组织核查事项，意见和多处证据持续归属同一事项。同一段落的不同规则分别保留。关联核对时主事项不变；返回恢复事项原文并保持暂停。刷新记录按审查批次、正文版本及尝试隔离，只保存不含正文的身份键。

正文仅由用户点击引用、目录或上一条／下一条触发定位。任务启动、结束、意见到达、状态刷新均不自动滚动或切换原文。已移除自动跟随入口、停留节奏与自动推进调度；旧跟随偏好不会恢复。后台审查和事项进度继续更新。

当前已验证固定版本实际合同 100 段、合成样例 18 段（含普通表格重复单元格、跨页长段、Unicode）。不代表任意嵌套表格、浮动文本框、脚注或其他 OnlyOffice 版本均兼容。部署升级须重新执行映射与定位验收。

## 引用标签与结果浏览（navigation 15）

意见旁直接展示按证据身份区分的引用标签；同名标签不会参与定位匹配。仅在编辑器确认目标可见后标记“当前”。结果浏览无需活动核查任务，不能因没有活动事项清除人工定位标记。同一段落内不同范围也支持关联核对与返回。

定位结果保留 geometry/status/reason，由宿主区分完整范围、仅起点、映射歧义与正文失效。页边标签以整个当前段落的左边界计算，不能以行中证据起点误判页边；边距不足时由宿主显示状态，不覆盖正文。

## 审阅工具栏初始化（navigation 17）

可编辑会话在文档首次就绪、桥接能力校验成功后打开原生“审阅”页签。开启修订和选择工具栏是独立操作；自动选择仅执行一次，不放在 mode、保存或审查完成的回调里，保留用户随后选择的页签。只读会话保留原生默认工具栏。自动打开失败时提示手动点击，正文仍可正常加载。

`review` 命令现在检查页签存在、可见并在点击后已激活，失败返回错误，避免缺少控件时假报成功。发布入口使用带内容哈希的桥接地址。

## 文档校对语言（navigation 18；初始化行为已修正）

打开文档不再自动设置校对语言，保留原文件属性。中文界面由 `editorConfig.lang=zh-CN` 独立配置，默认关闭拼写红线也不修改文件。用户可通过底部“设置文档语言”主动调整，这属于真实文档修改。

allowlist 命令 `defaultLanguage` 仍保留为显式操作能力，通过原生 `asc_setDefaultLanguage(2052)` 设置简体中文，与底部“设置文档语言”一致；宿主初始化不调用。若已是中文则不重复修改；只读、保存冻结或 SDK 拒绝修改时明确报错。显式指定的文字语言仍保留。

该操作真实修改 DOCX 默认语言属性，走原有 dirty、自动保存、版本入库流程，可能产生新的文档版本，不能当成纯显示变更。zh-CN 界面配置本身不修改此属性。当前部署没有中文拼写词典，中文语言设置不代表具备中文纠错能力。

历史验证确认：自动设置会把保存文件的 docDefaults/w:lang/@w:val 从 en-US 改为 zh-CN，即使正文文字未变也会触发新版本。因此取消自动设置，而非忽略 dirty 事件、跳过保存或取消审查过期保护。

## 关闭拼写红线（navigation 19）

宿主在每次文档就绪、能力检查成功后发送 `disableSpellcheck`，通过原生 `asc_setSpellCheck(false)` 关闭拼写检查，并同步 `spelling:turn` 控件状态。可编辑和只读会话均执行，不依赖 DOCX 的语言属性，也不会被浏览器之前保存的开启偏好覆盖。用户可在当前会话手动开启，重新打开仍默认关闭。

该操作不改正文、下划线格式、修订或批注，不生成文档版本。已验证拼写按钮首次加载为关闭、手动开启后刷新恢复关闭及只读会话加载；113 项前端测试、34 项桥接测试及生产构建通过。


## 建议应用与原生批注（navigation 24）

新增白名单命令 `applyProposal`；host 只传服务端 prepare 返回的操作 ID、正文版本、结构锚点、建议文本及模式（ALL / COMMENT / MODIFY）。默认按钮可设为三种操作之一。仅 completed / needs_input 批次的 draft 建议可申请写入；后端拒绝资料变化、非本系统应用造成的版本变化、目标原文变化及表格目标。普通单段替换之外的插入、删除、跨段写入尚未开放，可继续复制建议。

原生范围通过完整段落映射和段内出现位置校验；SDK `asc_AddText` 在启用跟踪更改时替换选区。首期以目标引用整体替换，卡片内仍按字符显示对比，不宣称已实现逐个差异片段写入。段内已有修订、批注或复杂行内内容时拒绝覆盖。替换后再将书签、批注绑定到新增文字，避免原生替换删除预先插入的标记。COMMENT 模式不替换正文。Builder GetText 包含删除文本，简单段落通过 ToJSON 的 reviewType 还原 proposed 文本；未知结构拒绝绑定，不猜偏移。

客户端保留操作回执防止重复写入；服务端 proposal_operations 独立记录 prepared / applied / reverted / cancelled。apply 成功不等于保存成功：保存屏障及回调确认后，服务端核对全文 proposed 文本、操作书签、新增修订、批注内容及范围标记，才把卡片标为已应用。失败保留“重试保存确认”和“撤销未完成操作”，不自动重放写入。

撤销采用受限的保存快照回退：仅当当前 head 仍是该操作的确认版本时，恢复其 before_version 原始 DOCX 字节，新建版本并关闭旧 document key，重新加载编辑器。已存在后续修改时拒绝回退；本期不支持跨过后续操作选择性撤销，也不调用全局接受／拒绝全部修订。未完成操作只允许在关联保存回执及全文与预期一致时撤回。重新加载及重复回调不能覆盖撤回版本。

真实验证使用武威东润合同的 data_purpose=test 副本和已有 LLM 输出，未触发新模型审查、未修改业务原件。三种模式、刷新恢复、页面导出 DOCX 和撤销均完成验证；导出与已确认版本字节相同，撤销恢复与操作前文件字节相同。OnlyOffice 保存会规范化样式 ID、部分字符缩进元数据；本次没有声称 OOXML 属性逐字保持或任意复杂版式无损。


## 连续补做与写入恢复（navigation 28）

`applyProposal` 接受服务端生成的 `continuation`，通过前一次已核验书签定位补做范围。保存文件中的 `ooxml_comment_id` 与 SDK 运行时编号不是同一个命名空间；默认按唯一内容、作者与引文匹配原批注，仅显式 `runtime_comment_id` 可查询 SDK。无回复、未解决的自有批注才可在替换后迁移，保留作者与用户标识；有回复或重叠线程时拒绝迁移。

此固定构建的 `ApiRange.GetText` 在存在删除修订时可能拼入范围之外的旧文字。写入选区、结果搜索和补做书签改用严格单段 `ToJSON` 文本校验，拒绝复杂结构及不匹配的结果；原生范围仍由编辑器生成，不将解析器偏移直接当成 SDK 位置。

`inspectProposal` 只读返回 `present / absent / uncertain`，优先查操作回执；存在未保存修改时不能报告缺失。宿主丢失消息时查询状态，禁止重放可能已执行的内容修改。回执本身不代表保存成功，仍须由后端核验保存文件。宿主要求能力版本至少 28。

## 定位失败诊断与局部绑定（navigation 29）

显式原文定位使用 `bindAnchors({allowPartial:true})`。完整有序映射失败时，仅绑定在保存版本和编辑器中完整文字均唯一的段落；重复或缺失段落分别返回 `ambiguous` / `not_found`。该回退不进行近似匹配，仍校验版本、保存状态、引用字符范围及实际选区文字。修订写入不启用此参数，继续要求完整映射。

宿主将具体失败向上传递，并保留 `status / reason / sourceIndex`；失败后使绑定缓存失效，重试重新建立映射。界面保留返回原文入口，但不宣称实际滚动位置已恢复。

## 跨修订删除的引用定位（navigation 30）

第 7.3 条带删除修订的实文复现：后端 proposed 文本排除被删的“费”，OnlyOffice Search 仍搜索含删除文字的原文，因此完整引文无法命中。显式定位在搜索无法校验时，使用单段范围 JSON 的 proposed 文本验证整段，再通过前缀二分把 Unicode 偏移转换成 SDK 范围位置；最终范围和实际选区都必须逐字等于引用。未知内联结构拒绝该回退，修订写入继续使用原路径。

本地审查入口 `http://127.0.0.1:5190` 已纳入桥接来源白名单（navigation 31）。该入口的 API 需启用 ONLYOFFICE，并将容器回调地址设为对应 API 的端口；仅启动未配置编辑器的 API 会导致“正文未能打开”。


## 静态资源缓存升级（2026-11-19）

安装脚本根据桥接文件 SHA-256 的前 16 位生成资源 URL，并同步完整构建脚本，避免同一 navigation 能力版本内的修改沿用旧 URL。发布清单同时校验自定义 Service Worker 与 nginx 路由。

`editor-service-worker.js` 替换本定制构建的 worker：`web-apps/` 使用网络及正常 HTTP 缓存语义；SDK、字体等固定资源保留缓存加速，但不读写 `no-store` 响应。激活时只清理当前构建静态缓存中的可变前端和 `no-store` 项，不清理文档缓存、登录状态或其他构建。文档下载与回调由正常网络处理，不使用原 worker 的动态文件缓存。

安装后需使 nginx 加载新增的精确 worker 路由（本地容器：`docker exec onlyoffice-ui-lab-docs-1 nginx -t`，通过后执行 `docker exec onlyoffice-ui-lab-docs-1 nginx -s reload`）。部署检查 worker URL 应返回 `Cache-Control: no-store` 及新的脚本。已有窗口加载新 worker 后通过页面内“重新加载”重建编辑器；该按钮保留现有保存屏障。更新 worker 不会自动重载正在编辑的文档。
